# VILKA — інтернет-магазин і маркетплейс

VILKA — навчальний вебпроєкт на Django REST Framework із HTML/CSS/JavaScript фронтендом. Проєкт містить каталог товарів, кошик, оформлення замовлень, авторизацію, особистий кабінет та оголошення користувачів.

## Можливості

- реєстрація, вхід і вихід через Token Authentication;
- каталог товарів і перегляд товару;
- кошик у `localStorage`;
- оформлення замовлення тільки авторизованим користувачем;
- серверний розрахунок суми замовлення за актуальними цінами;
- серверна перевірка залишків із транзакцією та блокуванням товарів;
- користувач бачить тільки власні замовлення, адміністратор — усі;
- історія замовлень в особистому кабінеті;
- створення оголошень лише після авторизації;
- власник може редагувати/видаляти власне оголошення, адміністратор — будь-яке;
- публічний перегляд активних оголошень;
- перевірка цін, кількостей, доставки та інших вхідних даних на сервері.

## Структура

- `backend/` — Django-проєкт і API;
- `backend/accounts/` — користувачі, профілі, авторизація;
- `backend/shop/` — товари;
- `backend/orders/` — замовлення та позиції замовлення;
- `backend/announcements/` — оголошення маркетплейсу;
- `backend/templates/` — HTML-сторінки;
- `css/` — стилі;
- `js/` — JavaScript фронтенду;
- `media/` — завантажені зображення (створюється локально).

## Встановлення

1. Встановіть Python 3.12+.
2. Відкрийте PowerShell у папці `magaz/backend`.
3. Створіть середовище: `python -m venv venv`.
4. Активуйте його: `venv\Scripts\Activate.ps1`.
5. Встановіть залежності: `pip install -r requirements.txt`.
6. Виконайте міграції: `python manage.py migrate`.
7. За потреби створіть адміністратора: `python manage.py createsuperuser`.

## Запуск

У `backend`:

```powershell
python manage.py runserver
```

Після запуску відкрийте `http://127.0.0.1:8000/`.

Для розробки фронтенд також може обслуговуватися через Django. Якщо запускаєте HTML окремим сервером, його origin має бути доданий до `CORS_ALLOWED_ORIGINS` у `backend/config/settings.py`.

## API

### Акаунти

- `POST /api/accounts/register/` — реєстрація;
- `POST /api/accounts/login/` — вхід;
- `POST /api/accounts/logout/` — вихід;
- `GET/PATCH /api/accounts/me/` — поточний профіль.

### Товари

- `GET /api/products/` — список товарів;
- `GET /api/products/<id>/` — товар.

### Замовлення

- `POST /api/orders/create/` — створення замовлення, тільки авторизованим;
- `GET /api/orders/` — власні замовлення; staff/superuser бачить усі;
- `GET /api/orders/<id>/` — власне замовлення або замовлення для адміністратора.

### Оголошення

- `GET /api/announcements/` — активні оголошення;
- `POST /api/announcements/create/` — створення, тільки авторизованим;
- `GET /api/announcements/<id>/` — перегляд;
- `PUT/PATCH /api/announcements/<id>/` — тільки власник або адміністратор;
- `DELETE /api/announcements/<id>/delete/` — тільки власник або адміністратор.

Для захищених API використовуйте заголовок:

```text
Authorization: Token <TOKEN>
```

## Безпека

Критичні права доступу перевіряються на сервері, а не лише JavaScript-кодом. Клієнтська ціна та залишок не використовуються як джерело істини: сервер отримує товар із БД, перевіряє актуальний stock і сам рахує суму.

Для production потрібно вимкнути `DEBUG`, винести `SECRET_KEY` у змінну середовища, налаштувати HTTPS, hosts/CORS і окрему production-базу даних.
